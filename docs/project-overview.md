# Arm Vector — 실시간 팔 미러링 로봇팔 프로젝트 완전 정리

> 웹캠으로 사람 팔 자세를 읽어 6DOF 로봇팔이 실시간으로 따라 하게 만든 프로젝트. 원리·구조·과정·삽질·배운 것을 전부 남긴다. (반년 뒤의 나를 위해)

---

## 0. 한눈에

- **무엇:** 단일 웹캠 → 사람 오른팔 자세 인식 → 기하 계산 → 6DOF 로봇팔이 실시간 미러링
- **왜(발표 주제):** 기하 심화탐구보고서 — "교과서처럼 값이 미리 주어진 게 아니라, **연속으로 변하는 실제 공간의 값**에도 고전 기하 연산이 그대로 통하는가?"
- **핵심 결론:** 각 순간의 공식은 옳지만, **연속으로 변하면** 교과서엔 없던 문제(각도 경계 튐, 짐벌락)가 터진다. 그 극복이 회전군 SO(3)·쿼터니언.

---

## 1. 시스템 구조 (데이터 흐름)

```
웹캠 영상
  │
  ▼  MediaPipe (Pose + Hand landmarks)  ── 브라우저(index.html)에서 실행
관절점 3D 좌표 (어깨·팔꿈치·손목·손)
  │
  ▼  기하 계산 (JS)
5개 관절각 (CH0~CH4)
  │
  ▼  Web Serial API (USB)
Arduino Uno
  │
  ▼  PCA9685 (16채널 PWM 드라이버, I2C)
6개 서보 (DS3218) → 로봇팔 관절 구동
```

- **브라우저가 두뇌:** 인식·계산은 전부 노트북 브라우저(index.html). 아두이노는 각도 5개 받아 서보만 돌림.
- **펌웨어(.ino):** 각도→펄스 변환, 안전 제한(속도·가속도·중력·범위), 데드맨.

### 하드웨어
- 노트북: HP OMEN 16 (RTX 5070 Laptop, MediaPipe GPU 가속)
- Arduino Uno + PCA9685 + DS3218 서보 6개 + AliExpress 6DOF 프레임
- 전원: 18650 리튬전지 (**1셀 = 약 3.7~4.2V**로 최종 안착)

### 축 배치 (5축 사용)
| 채널 | 관절 | 매핑 방식 |
|---|---|---|
| CH0 | 베이스 회전 | 절대각 |
| CH1 | 어깨 상하 | 절대각 |
| CH2 | 팔꿈치 | 절대각 |
| CH3 | 손목 상하 | 상대각(등록자세 기준, 중심보간) |
| CH4 | 손목 축회전(비틀기) | 상대각(쿼터니언) |

## 2. 사용한 원리 (기하)

### (1) 팔 = 공간벡터의 사슬
관절점을 **공간좌표** 점으로, 팔 마디(상완·전완)를 **공간벡터**로 표현.

### (2) 팔꿈치 각도 = 내적
두 마디 벡터 사이 각:
```
cos θ = (u · f) / (|u| |f|)
```
(u = 상완 벡터, f = 전완 벡터) — 고등 벡터 내적 그대로.

### (3) 손바닥 법선 = 외적
손 위 두 벡터의 **외적**으로 손바닥이 향하는 방향(법선벡터) 계산. (외적은 고교 범위 밖 = 첫 상위개념)

### (4) 손목 자세 = 회전, 그리고 쿼터니언
- 방향(자세)은 좌표로 안 적힘 → **회전을 적는 문제**.
- 순진하게 각도(오일러 각)로 처리하면 → **짐벌락**(특정 자세에서 자유도 상실)에 걸려 값이 폭주.
- 그래서 **쿼터니언**으로: 회전축+회전각을 4개 수 $(w,x,y,z)$에 담아 4차원에서 연속 처리. 짐벌락·경계 튐 없음.
- 등록자세 기준 상대회전: `qDelta = qCurrent × conjugate(qReference)`, 이를 swing(CH3)·twist(CH4)로 분해.

### (5) 절대각 vs 상대각 (중요한 설계 결정)
- **CH0~CH3: 절대각 미러링** — 사람 각도 → 로봇 각도로 직접 선형 매핑(humanLo/Hi → robotLo/Hi). "상대 델타+스케일"은 진짜 미러링이 아니라서 절대각이 맞다.
- **CH4: 상대각(쿼터니언)** — 축회전은 절대 0점이 없는 누적값이라 상대각이 필수.

## 3. 만든 과정 (버전 흐름)

1. **초기(v1 계열):** 각도를 무지성으로 직접 매핑 → 로봇이 **사람이 불가능한 자세**로 움직임(관절이 반대로 꺾임 등). "상대 델타 스케일 = 미러링 아님"을 깨닫고 **절대각 매핑**으로 전환.
2. **손목 폭주:** CH4 축회전을 각도누적으로 처리 → 값 밀림·폭주 = **짐벌락**. **쿼터니언 상대각**으로 재작성.
3. **단일 기준자세 도입:** 등록·진단·시동에 쓰는 **통합 기준자세 하나**로 통일(팔 든 자세, 전완은 수직을 피해 눕힘 — 손목축 특이점 회피).
4. **중력 보호:** 무거운 축(CH1 어깨)이 고부하 자세에서 타는 걸 막는 **중력 가드**(2링크 무게중심 모델로 속도 감속). 초기엔 **로직이 정확히 반대로** 되어 있어 수정.
5. **재튜닝:** 서보 교체 후 각 축 CENTER/MIN/MAX를 **전용 캘리브레이션 스케치**로 재측정 → 모든 축 CENTER=1500us(기계중심)로 정리. 절대각 매핑에 더 잘 맞게 됨.
6. **첫 실물 시험(v10 계열):** PWM 활성화·안전·범위 제한 등 실기 전용 버전. 여기서 아래 하드웨어 삽질들 터짐.
7. **최종(v10.4):** 시동 트리거 3모드(엔터즉시/손목확인/전체자세) + COM 포트 자동재연결.

## 4. 안전 장치 (서보 태워먹은 뒤 넣은 것들)

- **속도·가속도 제한:** 각 축 deg/s, deg/s² 상한. (= 미분 개념)
- **중력 가드:** 상완이 수평+전개일 때 최대 부하 → 속도 자동 감속(최대 0.35~0.6배).
- **범위 클램프:** HARD(기구 한계) / TELEOP(그 안쪽 마진) 이중 제한.
- **첫 실기 ±제한:** 시동 초기엔 STOW 주변 좁은 범위로만.
- **데드맨:** 명령 끊기면 0.9초 홀드 → 5초 STOW 복귀 → 15초 PWM OFF.
- **단일 클릭 PWM + 긴급정지:** (2단 확인은 오히려 안 켜지는 문제 있어 단일 클릭으로 단순화)
- 이 중 여러 개가 **브라우저·펌웨어 양쪽에 이중** 적용(통신 끊겨도 펌웨어가 독립 보호).

## 5. 트러블슈팅 이력 (= 삽질, = 제일 값진 부분)

| 증상 | 진짜 원인 | 해결 |
|---|---|---|
| 로봇이 인간 불가능 자세로 움직임 | 델타+스케일 매핑(미러링 아님) | 절대각 매핑 |
| 손목이 무한 회전·폭주 | 오일러각 짐벌락 | 쿼터니언 상대각 |
| 처음부터 로봇 구동 안 됨(2S) | 2셀 8.4V가 서보(DS3218 상한 6.8V) 초과 | 1셀로 교체 |
| 중력 가드가 이상하게 동작 | 감속 로직이 정확히 반대 | 부호 수정 |
| 어깨 각도 누적 밀림(-90→-170) | CH0가 절대축인데 누적기 사용 | 매 프레임 절대값 사용 |
| 발표날 구동 안 됨 | Arduino IDE 업로드 COM 포트 바뀜(COM3→6) | 재업로드 / v10.4에서 웹앱 자동재연결 |
| 시동 자세가 안 잡힘 | 5축 전체 일치 요구가 너무 엄격 | 임계 완화 + 결국 "엔터즉시" 모드 |
| PWM 안 켜짐 | 8초 2단 확인 창이 만료 | 단일 클릭으로 단순화 |

### 특히 하드웨어 대참사 (발표 6일 전)
- 구동이 갑자기 멈춤 → **배터리 문제로 2일간 오판.** 배터리·홀더 교체, 18650 계속 굴림.
- **멀티미터가 없어서** 전압 확인을 **+선과 -선을 비벼 스파크로** 했음. (하지 말 것)
- 220V 전원이 필요했는데 **Ali에서 110V를 잘못 주문** → 안 됨 → **110→220 변환기**를 또 사서 무작정 연결 → **PCA9685에서 연기.**
- 그런데 PCA칩은 그 뒤에도 구동됨(=완전 사망은 아님. 단, 부분 손상 가능성 있으니 새 칩 교체 권장).
- **진짜 원인은 처음부터 전압/전류(언더볼트)** — 서보가 브라운아웃. 정격 전원 주니 정상.

## 6. 최종 시동 방법 (v10.4 기준)

1. 펌웨어(v7.4)를 서보 외부전원 OFF 상태로 업로드 (한 번 하면 칩에 남음, 재업로드 불필요)
2. 브라우저에서 index v10.4 열기 → ▶ 시작
3. **시동 모드 "엔터즉시"** (기본)
4. 🤖 로봇 연결 (COM 자동재연결됨)
5. 외부 서보전원 ON(1셀) → ⚡ PWM 켜기
6. **손바닥이 화면을 향하게 하고 엔터** → 그 순간 자세로 즉시 동기화 + 미러링 시작

> 절대각 매핑이라 몸통 자세는 아무렇게나 잡아도 로봇이 알아서 맞음. 손바닥(손목 인식)만 맞추면 됨.

## 7. 알려진 한계

- **CH1(어깨, 35kg 서보)이 굼뜸** — 1셀 저전압이라 토크 부족(물리적 한계). 정격 전압이면 해소.
- **단일 카메라** — 3D 복원이 완벽친 않음. 두 번째 카메라면 상당수 난점이 사라졌을 것(교훈).
- **PCA9685 연기 이력** — 부분 손상 가능. 새 칩 교체 권장.

## 8. 배운 것 (원칙)

- **근본 원인 우선:** 여러 삽질이 정교한 모델이 아니라 단순 물리(전압·배터리홀더)에서 났다. **소프트 의심 전에 하드웨어·전원부터 확인.**
- **전압 규율:** 서보 정격 vs 공급 전압 반드시 대조. (2S 8.4V > DS3218 6.8V가 최초 미작동의 근본원인)
- **연속성이 기하 실패를 드러낸다:** 순간 계산은 다 옳다. 실패는 시간축에서만 나타남(경계 튐, 짐벌락) — 이게 프로젝트의 지적 핵심.
- **절대각 vs 상대각:** 진짜 미러링엔 절대각. CH4만 예외(누적).
- **한 축씩 검증:** 서보 태운 이력 때문에, 5축 동시보다 한 축씩 안전하게.
- **멀티미터 사라.** (제발)
