## 0. 지금 당장 다음에 할 일 (한 줄 요약)

**사용자가 로봇팔을 재튜닝해서 새 기준자세 기준 CH0~CH4의 CENTER/MIN/MAX 각도(deg/pulse/us)를 측정해 오는 중이다. 그 값을 받아서 index v9.8과 firmware v7.0의 보정 배열(현재 전부 NaN 잠금)에 채워 넣는 것이 다음 작업이다.**

값 받으면:
- 각 값이 어느 상수에 들어가는지 정확히 짚어서 넣는다
- 넣기 전 산술 검산(deg↔pulse↔us 일관성) 먼저 한다
- CH2는 절대각 미러링용 끝점, 나머지는 상대각용 CENTER/MIN/MAX

## 1. ★★★ 단일 기준 자세 (가장 중요 — 이번 세션 최종 결정) ★★★

사용자가 사진으로 확정한 **하나의 자세**를 모든 모드의 기준으로 통일했다.

**자세 (오른팔 기준):**
- 팔을 위로 들어올림 (상완이 위쪽 대각선, 팔꿈치가 어깨보다 높음)
- 팔꿈치 약간 굽힘 (손이 머리 위로)
- **전완을 살짝 기울임** ← 의도적. 전완이 수직이 되면 손목 기준축(downRef)이 붕괴하므로 이를 방지하려고 사용자가 일부러 기울인 것
- **손바닥 정면**(카메라 쪽) ← CH4 축회전 0점 확보용
- 왼팔(측정 안 하는 팔)은 자연스럽게 아래로

**이 자세 하나 = 다음 전부의 기준:**
```
시작 자세 = 자세 등록 = 진단 1번 기준자세 = ROM 측정 시작 자세 = 로봇 연결/시동 자세
```

**폐기된 것:** 이전 세션의 "아래팔 45° 권장"은 이 자세로 대체되어 **폐기**. 다음 세션에서 45° 관련 코드/안내가 있으면 이 자세 기준으로 교체할 것.

**중요 함의:** 이 자세는 전완을 기울여 손목 기준축 붕괴를 이미 방지했으므로, 전체 5축 시연 시 손목 기준축 걱정이 없다.

## 3. 매핑 방식 (이번 세션 핵심 변경 — v9.8)

사용자가 "지금 방식은 동기화가 아니다"라고 정확히 지적. 상대각+스케일링은 미러링이 아니었음.
→ **발표 시연용이라 작은 오차는 감수 가능**하다는 판단으로 **절대각 미러링**으로 전환.

### 축별 매핑 방식
| 축 | 방식 | 이유 |
|---|---|---|
| CH0 어깨좌우 | 절대각 (끝점 미설정) | 로봇 값 받으면 채움 |
| CH1 어깨상하 | 절대각 (끝점 미설정) | 로봇 값 받으면 채움 |
| **CH2 팔꿈치** | **절대각 미러링 (구현 완료)** | 사람 각도→로봇 각도 직접 변환 |
| CH3 손목상하 | 절대각 (끝점 미설정) | 로봇 값 받으면 채움 |
| CH4 손목축회전 | **상대각 유지 (필수)** | 연속 누적값이라 절대 0점이 없음 → 절대각 불가능 |

### 절대각 미러링이란
- 사람 관절 각도를 로봇 서보 각도로 **직접 선형 변환**
- 사람이 L자(90°) 만들면 로봇도 **시각적으로** L자 (서보 숫자는 106°지만 모양은 L자)
- **"같은 각도"의 두 의미 구분**:
  - ① 숫자가 같다 (사람90°=로봇서보90°) → **불가능** (로봇 기구학이 다름)
  - ② 시각적 모양이 같다 → **이게 목표, 가능**
- **ROM 측정 불필요** (양끝점을 해부학+로봇실측으로 아니까). 단 CH4만 ROM/상대각 필요

### CH2 검증된 매핑 예시 (로봇 실측 CENTER=107.44 기준, 미리 계산됨)
```
사람 팔꿈치 0°(편 팔)   → 로봇 CH2 175°
사람 팔꿈치 90°(L자)    → 로봇 CH2 106°
사람 팔꿈치 150°(접음)  → 로봇 CH2 60°
```
(주의: 위 로봇값은 사용자가 재튜닝 중이므로 **새 기준자세 기준으로 바뀔 수 있음**. 새 값으로 갱신 필요)

### 구현 위치 (index v9.8)
```javascript
const ABSOLUTE_MAP=[
  {mode:'absolute', humanLo:-90, humanHi:90,  robotLo:NaN, robotHi:NaN}, // CH0
  {mode:'absolute', humanLo:0,   humanHi:180, robotLo:NaN, robotHi:NaN}, // CH1
  {mode:'absolute', humanLo:0,   humanHi:150, robotLo:NaN, robotHi:NaN}, // CH2 ← robotLo/Hi 채워야
  {mode:'absolute', humanLo:-70, humanHi:70,  robotLo:NaN, robotHi:NaN}, // CH3
  {mode:'relative'}                                                       // CH4
];
```
- `absoluteHumanToServo(raw,i)` 함수가 humanLo→robotLo, humanHi→robotHi 선형 대응
- `rawToServos`가 축별 분기: absolute면 직접 변환, relative면 기존 상대각
- `hardwareConfigValid`가 절대각 축은 끝점 4개 검증, 상대각 축(CH4)만 HUMAN_ROM_PROFILE 검증

## 7. 이번 세션까지 수정한 버그 이력 (v9.0 → v9.8)

시간순으로 발견하고 고친 것들. 회귀 방지용.

1. **진단 자세 개편** (v9.1): 11→13자세, 손목 자세에 팔 자세 스펙 추가, 좌우 꺾기(혼입검사) 자세 신설
2. **손바닥 방향 오류** (v9.2): 코드 자연 영점이 "손바닥 바닥"임을 발견. 손목 자세를 손바닥 바닥 기준으로 재정의. 14자세
3. **중력가드 반전** (v9.3): CH1 177°=수평(최대부하)인데 코드는 수직(무부하)로 가정 → sin을 2링크 CoM 모델로 교체. STOW 100%→55%. ★서보 태운 원인 추정★
4. **손목 기준축 가드** (v9.3): 전완 수직이면 downRef 붕괴 → frameQuality 검사, 등록 거부
5. **bodyZ 부호 버그** (v9.4): bodyZ가 몸 뒤를 가리켜 "팔 앞"이 raw0 wrap 경계(±180°)에 앉음 → 오른팔에서만 폭주. 양팔 모두 앞 가리키게 수정. 실측 검증: forward raw0=183.3°(예측180°)
6. **누적기 freeze 버그** (v9.4): 팔 수직 시 prevRaw 낡은 채 남아 ±360° 주입. 재시드+클램프. 실측: twist_palm_in=-559.3°=160.7-2×360
7. **상대 쿼터니언 순서** (v9.6, GPT): qDelta=conj(qRef)×qCur → qCur×conj(qRef)로 수정
8. **손 게이트 완화** (v9.7): 0.16→0.28. v9.6에서 손 전량 버린 진범. 팔 배치 조금 달라도 손 잡힘
9. **기준자세 진행차단** (v9.7): 1번 실패 시 다음 자세 안 넘어감 (v9.6은 그냥 진행해 전체 무효)
10. **null→OK 판정 버그** (v9.7): 데이터 없는데 "혼입 OK"로 표시 → "데이터 부족"으로 정정
11. **손 지표 3분리** (v9.7): 검출/게이트통과/최종유효 따로. "손 검출 0%" 오해 제거
12. **팔 자세 실시간 HUD** (v9.7): 촬영 중 CH0/CH1/CH2 편차 표시, 벗어나면 빨강
13. **우클릭 캡처** (v9.7): 스페이스바 누르면 팔이 움직여 오차 → 반대손 마우스 우클릭으로 캡처
14. **CH2 절대각 미러링** (v9.8): 상대각→절대각. 진짜 미러링
15. **펌웨어 중력가드 반전 수정** (v7.0): index v9.3과 동일 2링크 CoM 모델

## 10. 실기 테스트 순서 (서보 보호)

1. 펌웨어 업로드 → 시리얼 모니터 `READY_5AXIS_...` 확인
2. `P` → `CAL_LOCKED`면 아직 잠김 / `CAL_OK`면 준비됨
3. 보정값 다 넣고 `CAL_OK` 확인
4. `E` → STOW에서 PWM 켜기
5. **CH2 한 축만** 손으로 천천히 → 로봇 따라오는지
6. 괜찮으면 전체 시연

시리얼 프로토콜: `a0,a1,a2,a3,a4\n`(5각도) / E=활성 / X=정지 / C=STOW / N=neutral / P=상태
