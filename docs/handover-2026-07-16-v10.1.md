# Arm Vector v10.1 — 오른팔 기준값 수집형 첫 실기

## 원인

v10.0은 CH0 시작값을 `0°`로 강제했지만, 실제 오른팔 진단 시작자세에서는 CH0가 `-90°`였고 현재 화면에서도 `-170.6°`처럼 음수로 측정됐다. 또 CH0가 절대축인데 프레임 차이를 계속 누적하던 코드가 남아 있어 값이 장시간 밀릴 수 있었다.

## v10.1 변경

- 첫 실기는 오른팔로 고정한다.
- CH0는 자세 등록 때 측정한 **현재 음수 중앙값**을 로봇 CH0 `140°`의 기준으로 저장한다.
- 이후 CH0 변화량만 `1° : 1°`로 따라가며 브라우저와 펌웨어가 모두 `130~150°`로 제한한다.
- CH0 누적기를 제거하고 매 프레임 절대 raw를 사용한다.
- `-180°/+180°` 경계만 가까운 동치각으로 정리한다.
- CH1/CH2 기준은 기존 오른팔 유효 실측 `54.9° / 45.6°`를 사용한다.
- 현재 스크린샷 값 `[-170.6, 58.6, 42.3]`도 등록 허용 및 첫 실기 제한범위 안에 들어간다.
- 왼팔 전환은 첫 실기 제한모드 동안 차단한다.
- 저장값은 오른팔/버전 태그가 붙은 새 키를 사용해 v10.0 기준값과 섞이지 않는다.

## 사용할 파일

- 브라우저: `index-v10_1_right_arm_baseline_first_live.html`
- Arduino: `arm_firmware_v7_2_first_live_test.ino` (변경 없음)

Arduino는 사람 좌표를 해석하지 않고 브라우저가 보낸 서보각 5개만 검증·제한하므로, 이번 CH0 좌표 수정은 HTML에만 필요하다. 펌웨어의 PWM 2단 확인, STOW, 속도·가속도 제한, 중력 폴백, 데드맨, ±10° 제한은 그대로 유지한다.

## 테스트 순서

1. v7.2 펌웨어가 이미 업로드되어 있으면 다시 올릴 필요 없다.
2. 새 v10.1 HTML을 연다.
3. `▶ 시작` 후 오른팔을 화면에 둔다.
4. HUD의 `CH0 우팔 절대`가 음수인지 확인한다.
5. 어깨상하 약 `55°`, 팔꿈치 약 `46°`, 손목 곧게 자세에서 `📍 자세 등록`을 누른다.
6. `✅ 오른팔 기준값 수집 완료`가 떠야 한다. CH0 숫자는 -90이든 -170이든 그 순간 값이 기준이 된다.
7. 로봇 연결 → PWM 첫 클릭 → 구조 확인 → PWM 두 번째 클릭.
8. Enter로 시동한 뒤 CH0만 3~5° 정도 매우 천천히 움직여 방향을 확인한다.
9. 이상 방향·소리·떨림이면 즉시 긴급정지한다.

## 자동검수 결과

- 과거 오른팔 기준 `[-90.0, 54.9, 45.6]` 등록 통과
- 현재 스크린샷 `[-170.6, 58.6, 42.3]` 등록 통과
- 두 자세 모두 시작 명령이 펌웨어 제한 안쪽
- CH0 기준값에서 ±10° → 로봇 130~150° 정확히 제한
- `-179° → +179°` 경계 이동을 `-2°`로 처리
- HTML/펌웨어 보정 배열과 제한 배열 일치
- `strtof` 없음, AVR 호환 `strtod` 유지
- Worker 및 module JavaScript 문법 통과
